# 📘 Project Development Blueprint (项目开发蓝图)

> **将模糊的业务需求转化为可直接执行的开发蓝图，专为 AI 编码模型与人类开发者设计的“零猜测”实施参考。**

## 🎯 简介

`project-development-blueprint` 是一个系统化的分析与设计 Skill。它不直接编写业务代码，而是通过分析需求和现有代码库，生成一份**实施就绪（Implementation-Ready）** 的项目开发蓝图文档。

该蓝图确保其他开发人员或 AI 编码模型能够仅凭此文档独立构建项目，无需自行臆造关键架构决策或业务规则。

## ✨ 核心能力

-   **引导式需求澄清**：通过高影响力问题循环，将模糊想法转化为结构化目标、场景与约束。
-   **三层设计模型**：严格执行“需求转化 → 架构设计 → LLM 执行交接”的层级流转，杜绝从概念直接跳跃到代码。
-   **消费者台账验证**：为每个模块/接口建立生产-消费路径，通过“缺失测试”剔除无意义的投机性抽象。
-   **AI 功能专项设计**：针对 AI 特性明确提示词所有权、输出 Schema、错误映射及防伪造机制。
-   **分阶段执行提示词**：生成包含前置条件、文件变更、验收标准及停止条件的阶段性 Prompt，适配 AI 编码工具。
-   **严格质量关卡**：交付前自动核对需求/架构/任务一致性，标记假设与未知项，给出明确的实施裁定。

## 🚀 适用场景

| ✅ 推荐使用 | ❌ 不推荐使用 |
| :--- | :--- |
| 新项目从零开始架构设计 | 纯代码逻辑解释 |
| 现有代码库的重大功能扩展 | 小型机械性代码修改 |
| 需要 AI 编码模型独立实施的项目 | 已有完整获批计划的直接编码 |
| 需求模糊需系统性澄清的场景 | 简单的 Bug 修复或配置调整 |
| 跨模块/跨服务的复杂系统设计 | 无需设计文档的一次性脚本 |

## ⚙️ 工作流概览

1.  **选择分析模式**
    -   **现有项目**：读取代码库，描述现状后再提变更。
    -   **全新项目**：从需求推导最小充分架构。
    -   **混合模式**：以现有代码为上下文，仅设计新增部分。
2.  **通过六大分析关卡**
    确立目标 → 映射架构 → 维护消费者台账 → 定义模块契约 → 选择最小方案 → 明确验证标准
3.  **生成实施级细节**
    包含技术选型、API/数据契约、文件级任务列表、状态转换、AI 适配器边界、部署/回滚策略等。
4.  **质量门禁与裁定**
    扫描矛盾、未标记假设及伪造内容，最终输出裁定结果：
    `IMPLEMENTABLE` | `REDUCE_SCOPE` | `REVISE_DESIGN` | `NEEDS_EVIDENCE` | `NO_CHANGE_NEEDED`

## 📂 输出产物

根据项目规模自动选择模板：

-   **小型项目**：单份完整 Markdown 文档（组件少、无跨服务契约）。
-   **中大型项目**：拆分文档集 + 索引（多部署单元、持久化/API 契约、迁移等）。

> ⚠️ **重要声明**：此 Skill **仅生成并保存文档**。除非用户明确要求，否则不会修改业务代码、创建迁移、部署或更改外部系统。

## 📌 使用须知

-   所有重要声明均标记为 `VERIFIED`（已验证）、`INFERENCE`（推断）或 `UNKNOWN`（未知）。
-   绝不从代码中捏造业务规则、SLA、定价等，未确认项一律标记为假设。
-   “企业级”定义为基于证据的完整性，而非盲目堆砌分布式复杂度。
-   AI 功能设计中，**禁止将模拟/伪造结果呈现为生产行为**。
